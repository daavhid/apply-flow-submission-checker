# Release variants and branch workflow

Full SQC 1.6.25 normalizes structured skill objects to unique display/AI skill names and falls back to parsed employment records when server facts omit workHistory. The final sidebar answer check, scan bindings and page announcements no longer treat a progress-only jobVersion update as a changed candidate/resume. Job/candidate/assignment/resume versions and job title/company changes still invalidate the appropriate UI operations; screening API request/response checks remain strict. Shared settings default ApplyFlow originals to PDF, request preferredResumeFormat=pdf and select an explicit PDF file variant when provided. DOCX-only delivery is surfaced as a missing-PDF error instead of automatic Word attachment. PDF bytes and supplied hashes are checked; local original uploads keep their actual file type. Actual deployed PDF field shapes still require the backend contract to match.

Full SQC 1.6.24 embeds https://applyflow-api.jhproit.com as the default API in config/connection.js. A clean installation starts at email/password sign-in without requiring a workspace URL. The default is initialized as signed out, so the extension never silently adopts a website login. Explicit saved workspace selections remain intact; no credentials are packaged. Tests cover fresh config, direct login, worker restart, logout and saved workspace preservation.

Full SQC 1.6.23 fixes the remaining Rippling CV false negative after inspecting its public form markup and FileIcon/Chip rendering code. Rippling's filename can be direct text inside a clickable Chip under a multi-ID ARIA-labelled upload area; stripping button descendants or scanning only filename spans misses it. The shared detector now reads that scoped chip, resolves the actual CV label and recognizes its hidden native file input through the visible label. The file audit value is synchronized with visible chip evidence. Sidebar reads re-check current attachment evidence and revalidate stale missing-resume errors without waiting for another form edit. The regression reproduces the clickable-chip structure, literal truncated text, multiple ARIA IDs and hidden input, and checks removal and stale-cache recovery. No live file upload was made during public-page inspection.

Full SQC 1.6.22 preserves account/origin-bound recovery IDs and original local documents when authorization expires. Verification leases and authenticated actions are still invalidated; explicit logout/disconnect clears recovery. Browser startup detaches old tab IDs instead of deleting all records, allowing restored tabs to recover only through an exact, unambiguous previously observed page match. Ambiguous candidate matches and unrelated recycled tab IDs cannot choose a saved assignment. Verification errors now include the actual request IDs, and the sidebar distinguishes complete retained IDs rejected by ApplyFlow from a missing ID set. Tests cover expired sessions, sign-in, original-document retention, changed tab IDs and ambiguous page matches. Previously deleted IDs cannot be reconstructed by this update.

Full SQC 1.6.21 recognizes uploaded CV chips beside nested inline headings used by Rippling, including close icons, truncated display text and full filename metadata. The shared form-state detector stops before unrelated fields or Cover Letter labels, and removed CVs cannot inherit the other attachment or stale cached state. Custom dropdowns are extracted and validated as labelled widgets, rather than their internal Search inputs. Generic Search accessibility text no longer overrides the actual question label. Rippling-style Chrome fixtures cover attached/removed CVs, optional Pronouns, an answered required Country and a genuinely unanswered required dropdown. These tests check visible portal state; they do not assert the external site's upload transaction.

Full SQC 1.6.20 fixes the copyButton reference error introduced by the education preview in 1.6.19. Education rendering now runs alongside the existing resume facts renderer, where its copy helper is defined. The sidebar Chrome fixture now includes actual education records and exercises rendering, copying and subsequent refresh, closing the empty-education test gap. The error was in SQC rendering and does not establish whether the employer accepted a resume upload.

Full SQC 1.6.19 re-detects the same document/upload control when attaching an original resume across a status-only jobVersion update. Candidate, assignment and original-resume changes remain strict; AI-answer checks are unchanged. Uploaded originals no longer inherit a stale base-generator warning. Education records are parsed from the actual resume, previewed separately and mapped to education fields without borrowing the candidate's city or inventing GPA. An explicit Fill education & work history action fills visible native rows, adds supported missing rows, maps split month/year fields and selects only unique exact custom options with readback. Manual edits are preserved and context changes stop asynchronous filling. Oracle-style Chrome fixtures cover row addition/order, education, exact degree selection and unchanged original PDF bytes; authenticated Oracle upload acceptance and arbitrary portal widgets are not asserted by these fixture checks.

Full SQC 1.6.18 keeps application-session/job/profile recovery IDs per tab in trusted local storage as well as session storage. Page and extension reloads can recover those IDs after redirects strip tracking; partial tracking parameters merge with the same application instead of replacing its full ID set. Each tab re-verifies independently with ApplyFlow before actions resume. A new tracked application replaces only its tab's recovery record; closed tabs, explicit sign-out/disconnect and a new browser session clear the relevant records to avoid reused tab IDs. Recovery never restores an expired lease or overrides a server denial. Tests cover lost session storage, alternating tabs with different jobs and candidates, new IDs, and denied/unrelated-account recovery.

Full SQC 1.6.17 lets recognized Next/Continue/Review transitions use the employer's native click and submit handlers. Whole-application validation and an expired SQC lease no longer cancel intermediate navigation; verified steps still capture tracking snapshots and screenshots. The portal's native validation remains active. Immediate requestSubmit calls without a submitter inherit the recognized step click, while final submission remains gated and completion still requires employer proof plus ApplyFlow acknowledgement. Decorated and accessible icon-only Next controls are recognized. Chrome regression coverage exercises both click and submit interception with invalid and expired context; the specific user's portal was not identified.

Full SQC 1.6.16 removes the content script's redundant forced session/context refresh before confirmation delivery. The worker still performs fresh final verification, without fetching original resume bytes. A correlated committed terminal status updates the cached application and returns immediately, without waiting for another status request. The sidebar receives a submission-change notification instead of waiting for its five-second poll. A visible confirmation with an expired lease triggers one immediate, deduplicated context recovery; the validator no longer displays Assignment verified as an unverified-context error. Screenshot capture and strict evidence/acknowledgement requirements remain. Regression tests assert the reduced request count and immediate lease recovery; live latency still depends on ApplyFlow and screenshot capture.

Full SQC 1.6.15 resolves application-event URLs from Chrome's current frame before backend verification and evidence validation, instead of relying on a potentially stale MessageSender URL after ATS SPA navigation. Replaced frame documents remain rejected. Evidence rejection identifies its failed checks, and the observation timestamp is refreshed after screenshot capture and the final visible-proof check. Regression coverage includes an Ashby iframe with differing original/current URLs, retained Q&A delivery, and rejection of changed documents or unrelated evidence URLs. This reproduces the integration failure mechanism in fixtures; live ApplyFlow acceptance still requires verification.

Full SQC 1.6.14 leaves employer link fragments, career filters, hidden widget IDs and focus management untouched. Tab tracking continues in the worker. It recognizes Ashby confirmation text including custom Application received messages, observes dynamically inserted or revealed notices, and reads submission delivery state from verified iframe documents for the same application. Previously captured answers remain available on confirmation. Passive Ashby job-selection messages are recorded locally for diagnostics; they never authorize a job or prove submission. Fixture tests cover delayed embedded applications and both reported confirmation messages; the exact reset event in the user's live browser has not been reproduced.

Full SQC 1.6.13 retains per-tab recovery claims after verification and across redirects, embeds and child tabs. It reads the real 409 error, refreshes the session once for explicit application-context version mismatches, preserves strict identity/version checks and exposes persistent server conflicts without losing the active workspace. Recovery diagnostics retain public ATS job identifiers and show the configured API origin. Mimica-style company wrappers and separately verified Ashby iframe URLs are regression-covered with another job open.

Full SQC 1.6.12 uses explicit candidate base-context location facts ahead of stale profile location values and rejects instruction words as cities. Matching session facts are preserved when job context omits the base text; the sidebar labels the location source. It also removes duplicate native-change/drop uploads, shares an automatic upload attempt guard across the sidebar and HUD, and reports visible portal file-upload rejections.

Full SQC 1.6.11 restores supported empty fields from the verified application's answer journal after refresh and optionally from a versioned savedApplication API response. It preserves manual edits, route/candidate/resume isolation and explicit clears. Required Country/location omissions and portal validation errors now appear in the sidebar, including missing selections in custom comboboxes. Credentials, consent and file-input values are not replayed.

Full SQC 1.6.10 detects visible employer confirmations even when the extractor retains answers from earlier steps. It removes the historical-field-count veto, ignores hidden wizard remnants and extension-owned success text, and shows Submitted / syncing or sync failed before acknowledgement. Completion delivery coalesces concurrent checks and retries with one persisted event ID. Current portal proof and verified context are rechecked for every attempt; only an acknowledged transaction shows completion. The Greenhouse confirmation regression retains nine fields, and failed delivery stays actionable in the sidebar.

Full SQC 1.6.8 hides the opener while the sidebar reports that it is visible, then restores it on hide/close/disconnect. The workspace reports document visibility and pagehide explicitly instead of treating every connected port as visible. A delayed job-status response cannot override a newer visibility notification. Successful open requests alone do not suppress the launcher before the panel confirms visibility. Host-style/overlay isolation and same-job availability recovery remain active while the panel is closed.

Full SQC 1.6.7 isolates the launcher host with important shadow styles and a nonmodal manual popover so ordinary host-page overlays and CSS cannot cover/hide it. It mounts outside the page body to avoid body clipping, transforms and inert application roots; host hidden/inert attributes and DOM removal are repaired. The same-page shortcut survives removal of ApplyFlow query tracking while preserving portal job-identifying query parameters. A real Chrome regression reproduced the previous CSS-hiding failure and now checks visible/clickable hit testing above a maximum-z-index page overlay. This is fixture coverage; the exact user's live-page cause has not been inspected. The button tooltip includes the installed extension version for diagnostics.

Full SQC 1.6.6 keeps the on-page sidebar opener available while the panel is reported open and during temporary verification failures on the same previously tracked page. An explicit click retries the native panel request even if its visibility report is stale. SPA removal of the opener restores it; launch-fragment cleanup keeps the same page shortcut. Unrelated routes still hide it and ordinary page interactions still require tracked/verified launch permission. This changes launcher availability, not assignment or autofill authorization.

Full SQC 1.6.5 / standalone Q&A 2.11.0 adds explicit **Assign to field** actions for answers and candidate contact details. The picker scans the current job for unanswered fields, permits reviewing/editing the value and applies through the same document/context and manual-edit guards as ordinary filling. Choice values must match exact options; document uploads remain separate. Changing the candidate/job while a mapping is open rejects it.

Greenhouse resume filename rows are also detected when the portal removes its native file input. The extractor and field inventory share that visible attachment evidence; Cover Letter remains separate. Overview shows the detected portal attachment explicitly, and DOM removals trigger revalidation. A visible empty resume control cannot inherit a stale uploaded filename from saved form state.

Full SQC 1.6.4 / standalone Q&A 2.10.0: progress now includes actual filled page fields, not only AI-generated answers. Greenhouse React Select committed values and uploaded filename chips are read without opening or changing controls. The Page field coverage inventory lists filled, unanswered and manual-upload controls; Workday form-label/select-widget and Lever/Ashby field containers are included in semantic detection. Conditional controls enter the inventory when rendered. Scanning continues past the 100-question generation batch limit.

Detection details report unlabeled controls, unsupported input types, manual controls/uploads and inaccessible frames. This is a coverage report for readable page controls, not a guarantee for closed shadow roots, inaccessible embedded documents, or every custom widget. Regression checks use synthetic platform markup and do not certify every live platform variant.

Errors are grouped into stable cards, with required fields in an expandable list. Identical refreshes retain the expanded state. Screenshots reuse identical images across triggers, replace the same step/viewport when the image changes, and skip automatic captures for unchanged form state, including scroll-only changes. Reload the extension and application tabs after upgrading so the new content scripts are active.

`main` contains the full SQC extension and the current Q&A sources. The standalone branch `feat/ai-questions-only` is preserved for the Q&A rollout. The older `feat/ai` branch is already an ancestor of main; the current Q&A work is on `feat/ai-questions-only`.

| Variant | Manifest | Runtime | Entry point |
| --- | --- | --- | --- |
| Full SQC + Q&A | `manifest.json` | `background/integrated-worker.js` | Toolbar opens the unified application sidebar |
| Standalone Q&A | `manifests/qa.json` | `ai/worker.js` | Toolbar opens Q&A directly |

The integrated worker loads both services. `QA_` messages are handled only by the Q&A listener; all SQC auth, assignments, HUD behavior and submission checks remain with the original service. The full release uses `sidebar/sidebar.html` with `background/sidebar-context.js` binding Q&A and resume actions to the active verified SQC job. Uploaded documents go through the same per-job resume service used by the submission gate. The standalone release continues to use its resume-only context. The full toolbar opens the unified sidebar directly; its legacy popup sources remain available only as supporting workspace UI.

On main:

```powershell
npm.cmd test
npm.cmd run test:browser
npm.cmd run test:browser:sqc
npm.cmd run build:all
```

Load `dist/extension` for the full release or `dist/qa/extension` for standalone Q&A. The ZIPs are `dist/submission-checker-extension.zip` and `dist/qa/applyflow-qa-extension.zip`. Each build replaces only its own unpacked folder and archive. On the original standalone branch, its existing default build still produces `dist/extension` and `dist/applyflow-qa-extension.zip`.

For later Q&A changes, keep working on `feat/ai-questions-only`, commit them, then merge that branch into main. Preserve the full main manifest and build profiles when resolving release-file conflicts; carry Q&A manifest changes into `manifests/qa.json`. Shared Q&A code lives in `ai/`. The main worker adapter resolves those imports from extension-root URLs and chooses toolbar behavior from the manifest, so both packages can use it. Keep main's unified sidebar and assigned-profile service when updating the standalone manifest.

Keep the dedicated API documents separate: `APPLYFLOW-INTEGRATION.txt` is the full SQC backend contract; `QA-INTEGRATION.txt` is the resume-only Q&A contract. Run all unit checks, Chrome Q&A checks and both builds after each merge. Verify the full package contains SQC and Q&A assets and the standalone package contains only Q&A assets. Publish either release independently when ready; a local merge does not publish or push it.
